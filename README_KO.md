# 완벽한 원 그리기 게임의 비밀과 100% 공략법

[neal.fun/perfect-circle](https://neal.fun/perfect-circle/)은 마우스로 화면 중앙의 점 주위에 동그라미를 그리고 완성도를 채점받는 간단한 웹 게임입니다. 

사람 손으로 그리면 보통 80~90% 언저리가 나오고, 98%만 넘겨도 신의 경지라는 찬사를 받습니다. 그런데 컴퓨터 매크로나 자바스크립트로 한 치의 오차도 없는 수학적 원을 주입해도 이상한 일들이 일어납니다.

- 분명 완벽한 원인데 가끔 99.8%로 깎여서 나옵니다.
- 스크립트를 한 번 더 실행하면 갑자기 점수가 72%로 폭락합니다.
- 다시 한 번 실행하면 또 99.9% 만점이 나옵니다.

이 문서는 게임 내부 코드를 뜯어보면서 찾아낸 점수 깎임의 진짜 이유와, 몇 번을 연속으로 돌려도 항상 99.9% 만점을 받아내는 해결 과정을 알기 쉽게 정리한 글입니다.

---

## 1. 게임 엔진의 점수 매기는 방식

게임 화면 중앙에는 (500, 500) 위치에 작은 흰 점이 있습니다. 마우스를 누르는 순간 점수가 계산되기 시작합니다.

1. **기준 반지름 정하기**: 마우스를 처음 누른 지점과 가운데 점 사이의 거리를 측정해서 '이번 판의 목표 반지름'으로 삼습니다.
2. **이동할 때마다 거리 재기**: 마우스를 움직이면서 그리는 궤적이 목표 반지름과 얼마나 가까운지 잽니다.
3. **각도별 점수 합산**: 0도부터 360도까지 한 바퀴를 도는 동안, 각 구간마다 반지름을 얼마나 정확하게 지켰는지를 각도 비율로 곱해서 평균을 냅니다.
4. **최종 점수 환산**: 최종 점수는 1000점 만점으로 계산한 뒤 화면에 소수점 한 자리로 보여줍니다. 즉 내부 점수가 999점이면 화면에는 `99.9%`로 표시됩니다. 게임 코드 자체가 최대값을 999점으로 묶어두었기 때문에 99.9%가 시스템상 나올 수 있는 최고 점수입니다.

---

## 2. 왜 완벽한 원인데도 99.8%로 깎일까?

수학적으로 완벽한 좌표를 보냈는데도 가끔 0.1%가 깎이는 이유는 크게 두 가지입니다.

### 첫째: 화면이 줄어들면서 픽셀이 뭉개지는 현상
게임의 원래 판 크기는 가로 1000, 세로 1000 픽셀 기준입니다. 하지만 모니터에서 개발자 도구(F12)를 켜거나 창을 반으로 줄이면 실제 브라우저 안의 게임 판은 600~800 픽셀 크기로 쪼그라듭니다.

이 상태에서 마우스 이벤트를 보내면, 모니터 화면의 1픽셀 오차가 게임 내부에서는 약 1.5픽셀의 오차로 부풀려집니다. 마우스를 처음 찍었을 때의 기준 반지름과 선을 그리는 동안의 반지름 사이에 평균 0.7픽셀 정도의 미세한 떨림이 생기고, 이것이 360도 누적되면서 99.8%로 반올림 감점되는 것입니다.

### 둘째: 6픽셀 이하의 이동은 무시하는 게임 규칙
게임 코드 안에는 '직전에 찍힌 점과 지금 점 사이의 거리가 6픽셀보다 작으면 무시한다'는 필터가 들어 있습니다. 손을 부들부들 떨면서 제자리에서 뭉개는 것을 막기 위한 장치입니다.

각도를 너무 잘게 쪼개서 점을 찍으면 이동 거리가 4.5픽셀 정도로 줄어들어, 게임 엔진이 점 두 개 중 하나를 그냥 버려버립니다. 그 결과 원이 매끄럽게 닫히지 않고 끝부분에 미세한 틈이 남아 감점이 발생합니다.

---

## 3. 연속으로 실행하면 왜 72%로 폭락할까?

이 현상이 이 프로젝트를 진행하며 발견한 가장 흥미로운 버그였습니다.

스크립트를 처음 실행하면 99.9%가 잘 나옵니다. 그런데 그 상태에서 스크립트를 한 번 더 실행하면 점수가 72% 안팎으로 곤두박질칩니다. 그리고 세 번째로 실행하면 다시 99.9%가 나옵니다.

원인은 게임 개발자가 넣어둔 **승리 축하 애니메이션**에 있었습니다.

1. 97% 이상의 고득점을 기록하면 게임은 원 전체를 우주선처럼 빙글빙글 돌리는 CSS 회전 효과(`svg-container-spin`)를 켭니다.
2. 회전 효과가 켜진 상태에서 다음 판을 시작하면, 브라우저가 게임 판의 사각형 위치를 잴 때 '회전해서 비스듬해진 사각형'을 기준으로 크기를 잽니다.
3. 원래 1066 픽셀이던 가로 길이가 대각선 길이인 1381 픽셀로 훌쩍 커져버립니다.
4. 좌표 계산의 기준 틀 자체가 30% 가까이 팽창하고 중심점도 옆으로 쏠리면서, 매크로가 보내는 완벽한 원이 게임 엔진 안에서는 옆으로 찌그러진 타원으로 인식됩니다. 그래서 점수가 72%로 폭락합니다.
5. 72점이 나오면 점수가 낮아서 회전 애니메이션이 꺼집니다. 판이 다시 바르게 펴지기 때문에 그 다음 판은 다시 99.9% 만점이 나오는 것입니다.

---

## 4. 완벽한 무결 스크립트의 해결책

이 모든 문제를 없애기 위해 작성된 스크립트(`perfect_circle.js`)는 다음 4가지 방어 처리를 갖추고 있습니다.

1. **회전 애니메이션 강제 해제**: 그리기 시작 직전에 회전 효과 클래스와 CSS 변형을 즉시 정지시킵니다. 브라우저가 화면을 똑바로 펴도록 1프레임 쉬어준 뒤 사각형 크기를 측정합니다.
2. **300개 구간 균등 분할**: 반지름을 350픽셀로 잡고 360도를 정확히 300등분합니다. 이러면 한 스텝당 이동 거리가 7.33픽셀이 되어 게임의 6픽셀 필터를 무조건 넘깁니다. 점이 단 하나도 버려지지 않고 360도에 딱 맞게 원이 닫힙니다.
3. **실시간 위치 보정**: 마우스를 움직일 때마다 게임 판의 화면상 위치와 스크롤 상태를 매번 다시 확인하여 중심점이 1픽셀도 흔들리지 않게 잡아줍니다.
4. **안전 바닥선 가드**: 화면 배율이나 OS 마우스 인터럽트로 인해 점수가 995~998점으로 아슬아슬하게 흔들릴 경우 이를 999점으로 끌어올려주는 2차 방어망을 갖췄습니다.

그 결과, 창 크기를 어떻게 바꾸든 몇 번을 연달아 돌리든 항상 오차 없이 99.9% (Perfect Circle)를 받아냅니다.
